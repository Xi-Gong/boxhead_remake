# v0.2.7 联机体验与发布审计

## 问题与目标

此前 LAN 保持严格输入等待，虽然加入了显示预测和延迟自适应，本机真实操作仍需经过输入缓冲并等待对端。60ms RTT 并不意味着按键到画面只有 60ms：输入采样、25Hz 模拟、缓冲、网络到达相位和显示刷新会叠加。只缩短缓冲会把延迟变成等待停顿，不能同时解决响应与抖动。

本次采用确定性回滚：本机输入在下一模拟 tick 生效，暂缺的远端输入先重复上一状态；收到真实输入后，从首次分歧之前的快照重放。上限约 240ms，超出窗口仍需等待，不能消除物理链路延迟。原模拟速度、RNG 次序、碰撞和战斗规则不变，显示刷新单独插值。本机武器声音允许提前播放，错误预测已播放的声音不能撤销；永久血迹/焦痕、解锁、检查点与终局必须等确认。

## 实现边界

- 默认协商 `rollback-v2`，不额外延后本机输入；旧能力路径继续使用既有锁步。TCP 原字段保留，新协议功能使用可选字段。
- 每 tick 保存输入执行前的世界，恢复空格导航、对象属性插入顺序和共享引用。实时与重放使用相同的模拟步骤和 tick 时钟。
- 完整状态摘要覆盖实体、弹体、地图格、集合、导航、升级、输入槽、RNG 和结算；只排除确认不被模拟读取的绘制缓存。比较共同确认时刻，不能把不同预测帧的瞬时差异当失步。
- 每显示帧插值远端实体并对本机玩家作碰撞约束外推，绘制结束恢复模拟位置；镜头和纠正偏移平滑。原 50Hz enterFrame、25Hz 默认模拟以及慢/快速度保持。
- 声音和永久贴花使用可重建事件账本；确认身份/顺序相同，本机预测枪声跨重放去重。回滚提前死亡时截断错误的未来帧与待确认事件。
- UDP 输入包重复携带最近 8 tick，限制包体 1200 字节，验证来源、令牌与局次；TCP 继续可靠承载输入副本、校验和控制。UDP 不可用时仍能联机。
- 暂停协调到共同确认边界。短断线先交换输入历史，保持原世界；历史不足或对端重启才从检查点恢复。DeathMatch 每 1500 tick 的检查点也在确认后提交。

## “玩家 2 重连”相关修复

确认修复了两个生命周期缺陷：旧 socket 的迟到回调可以关闭替换后的新连接；每秒发起重连又取消尚未完成、单端口可能等待 1.5 秒的前次连接。分别增加连接身份和待连接代次保护。

链路 watchdog、重连倒计时、等待计时改用单调时钟。输入不足、真正断线和校验失步分开：输入等待 500ms 后请求补发，不再将 6 秒等待谎报为 checksum 失步；30 秒未恢复按超时退出。最近 128 条诊断记录保留事件、tick 和确认前沿，传输断线还提供静默时长与 UDP 计数。

最终重启验收还发现，复用的主机会话保留旧 NetSlot 时间戳，而新客机从零开始，恢复后第 50 tick 校验仅输入槽不同而退出。重建游戏时原位重置输入槽，与新虚拟时钟一致；新增失败复现及相关 55 项回归通过。保留原世界的短断线历史恢复不重置输入。

这些是有失败复现的缺陷，尚不能断言是用户虚拟网卡周期性闪断的唯一原因。未在用户的真实 VPN 或对方机器上测量。

## 实测收益与代价

同机、同候选 asar、固定种子、相同分辨率和输入，旧/新模式交替各三轮。注入约 60ms RTT，3 秒预热、20 秒移动窗口；原半自动手枪持续按住仅少量开火，因此不是密集战斗基准。

| 三轮中位数 | 旧模式主机 / 客机 | 新模式主机 / 客机 |
|---|---|---|
| 按键至输入实际应用 | 110 / 94ms | 16 / 33ms |
| 呈现刷新率 | 50.0 / 50.0Hz | 120.4 / 120.4Hz |
| 每帧工作 p95 | 2.50 / 2.40ms | 2.80 / 2.60ms |
| 主线程忙碌比例 | 9.0 / 9.0% | 22.7 / 21.7% |
| GC 后 JS 堆 | 27.4 / 27.5MiB | 34.4 / 33.6MiB |
| 估计分配速率 | 3.1 / 3.1MiB/s | 43.6 / 32.6MiB/s |

输入探针读取实际输入槽，避免怪物推挤造成虚假“响应”；仅三次采样，不将中位数称为尾延迟。帧工作包括 enterFrame 之外的绘制准备。回滚和高刷新有明确成本，不宣称整体渲染更省资源。原始数据与方法见 [docs/verification/v0.2.7](../verification/v0.2.7/README.md)。

## 验证范围与发布状态

独立进程隔离全局 RNG，覆盖 0/30/60/100/200ms RTT、20/50ms 抖动、重复输入、主副本迟到、500ms 断流、暂停与原世界恢复、三档速度全 10 种武器、低画质对战及周期检查点。每组确认完整玩法、声音和贴花一致；这些故障是确定性调度，不冒充真实 VPN 丢包。

真实 TCP/UDP 测试验证屏蔽 TCP 输入写入后 UDP 仍能交付，以及 UDP 关闭后的 TCP 回退。离屏打包双端 60ms RTT 持续射击、真实断开连接并保留原世界恢复已通过。截图采用直接检查，结合几何、像素和真实点击验证，不声称使用了不可用的 zai 服务。

全量 Vitest 在追赶修复后通过 1318 项（71 项既有跳过）；随后会话结束释放调度的修正通过 54 项相关回归，其中包含 3 项新增失败复现。三套类型检查、构建和源码审计通过，117 个机械移植文件保持不变。浏览器 UI 188 项、音频 28 项、视口/输入/附加界面与三种模式、v019/v020 回归通过；开发版 Electron 原生窗口 46 项与三种模式通过。

首个候选的 60ms RTT 战斗长测持续 30 分钟，后半段双方无等待，15859 条确认声音身份/顺序及共同暂停完整状态一致，真实断线保留世界恢复。它也揭示了一端长期落后 3–4 tick：最终加入有预算的追赶，200ms 渲染缺口复现修复后通过，并确保结束/判负/销毁恢复调度。上表是该修复前的受控对照数据，不声称重新测量了最终构建。

用户明确要求缩短测试、尽快使用，故停止追加长跑及性能对照。100ms 长跑曾主动取消，不计通过；最终构建没有重新跑 30 分钟，也没有逐一重跑全部历史打包脚本。已通过的浏览器与开发版门禁、候选长跑不能替代这些未完成项目。本次不声称全发行门禁全部通过。

最终打包双端通过完整重启恢复：角色镜像、输入与声音、退出重连倒计时、传入检查点保留波次、恢复后持续运行并通过校验、认输结算、再次续局和30秒超时返回主菜单。旧测试切波夹具移入模拟tick并等待确认，未放松生产确认门禁。

最终 0.2.7 便携包通过真实 NSIS 启动、游玩、保存继续与 31 项声音解码检查。包内版本为 0.2.7，最终 SHA256 为 `B62D67C295CACF00BC964CF545387734FFDE73FC9FED22D1E291BB4D5A2C4771`。联机双方应使用同一版本；真实 VPN 与异机环境仍需用户实际体验验证。
